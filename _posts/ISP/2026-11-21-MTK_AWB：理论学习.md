![image\.png]({{ '/assets/ISP/remo-awb-theory/image 39.png' | asset_url }})

## A、HW Statistic 

`HW Statistic` 是 AWB 的前端数据采集模块，决定后续算法能够获得怎样的颜色信息。

主要包括：

```text
Sensor RAW
→ 应用 AWB PreGain1
→ 图像分块统计
→ 过滤暗像素、饱和像素和异常像素
→ 输出各窗口 RGB 数据
→ 转换为 XrYr
→ 送入光源估计模块
```

核心内容包括：

- **PreGain1 校正**：补偿不同 Sensor 模组的 R、G、B 响应差异，使相同光源在 AWB 坐标中的位置尽量一致。它主要用于模组一致性校准，不宜用于修正单一场景偏色。

- **分块统计**：画面被划分为大量统计窗口，文档示例为 `120×90`，每个窗口分别统计 R、G、B 和异常像素信息。

- **像素有效性过滤**：通过 RGB 高、低阈值排除过暗和近饱和像素，避免暗噪声、黑电平误差和通道饱和破坏颜色比例。

- **Error Pixel Ratio**：控制一个窗口内允许存在多少异常像素。数值增大可保留更多窗口，但污染风险增加；数值减小则统计更严格，但暗场可能缺少有效数据。

- **Linear Statistics**：AWB v5\.0 的重要改进。当窗口异常像素较多时，剔除异常像素并重新计算 RGB，从而在低照度下增加有效统计块，同时减小噪声对颜色结果的影响。

- **RGB 转 XrYr**：将统计 RGB 转换为 AWB 使用的二维色度坐标，便于后续判断统计点属于 Tungsten、CWF、Daylight、Shade 等光源区域。

## **B、Light Source Estimation**

```text
RAW硬件统计
→ Child Block光源分类
→ Parent Block投票
→ 各光源统计
→ 计算Statistic Gain和光源概率
→ 与Spatial/Temporal Gain融合
→ 输出Final AWB Gain
```

### **Child Block与Parent Block**

- 整幅图划分为 `120×90` 个 Child Block，共10800个。

- 每 `5×5` 个 Child Block组成1个 Parent Block。

- 最终得到 `24×18=432` 个 Parent Block。

- Analyzer中的散点主要反映Child Block的色度分布。

### **Pregain的作用**

`Pregain1 / Pregain1M / Pregain1L`主要用来校正不同模组在同一标准光源下的响应偏差。

- `Pregain1L`：低色温段；

- `Pregain1M`：中色温段；

- `Pregain1`：高色温段。

### **Child Block光源分类**

每个Child Block根据RGB统计转换到AWB坐标，再判断属于哪一个光源：T、WF、F、CWF、Daylight、Shade、DF或者判为Error、Non\-Neutral。

一个Parent Block内有25个Child Block。

1. 分别统计各光源个数；

2. 某光源个数大于阈值 `T0`，Parent Block归为该光源；

3. 只累加属于该主导光源的Child Block RGB；

4. 若没有光源超过 `T0`，则归为 `AWB_LIGHT_NONE`。

> `T0`大约等于每个Parent Block有效Child Block数量的一半。
> 
>

### **P0、P1、P2**

给每个光源概率 $$P(L_i)$$，概率越高该光源越可信，反之越低

**P0：统计支持度**

有多少加权 Parent Block 支持该光源。

$$
P0(L_i)=\frac{WPBN(L_i)}{\sum WPBN}
$$

- `WPBN`：前一节计算的加权 Parent Block 数量。

- PB越多、PB权重越大，P0越高。

P0 Stability：删除或压低很小的P0，避免少量误判光源干扰结果。如下

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 14.png' | asset_url }})



---

**P1：场景亮度先验**

当前场景亮度下，该光源出现是否合理。

$$
LV=EV-\log_2\left(\frac{ISO}{100}\right)
$$

根据当前LV查询每种光源的P1 LUT。P1越低：当前亮度下越不相信该光源。

如高LV场景通常会压低Tungsten、WF等人工暖光的P1。

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 21.png' | asset_url }})

> 调试: P1 通常应该在项目早期形成一个比较合理的整体曲线，后面**不频繁大改。**通常是针对有明确 LV/色温规律的问题
> 
> **低色温调试**
> 
> 真实光源用 D50/D65/Daylight 等**高色温光源**，但画面里主动加入：
> 
> 黄色墙、橙色墙、木板、咖啡色物体、暖色家具等容易落入 T/WF 区域的物体。
> 
> 然后覆盖不同 LV：
> 
> ```text
> High-CT真实光源
>       +
> 黄色/橙色等低色温混淆物
>       ↓
> LV 20 / 40 / 60 / 80 ...
>       ↓
> 观察 P0_T/WF、P1_T/WF、P2、Final P_T/WF
> ```
> 
> 如果某一 LV 下黄色墙让 `P_WF` 异常高，就逐渐降低该 LV 附近的 `P1_WF`，直到 **WF 不再因为混淆色错误占主导**。
> 
> 

---

**P2：绿偏／洋红偏可信度**

该光源统计相对光源曲线（普朗克曲线）的偏移是否合理。

根据Offset查询Weight LUT，Offset越大，P2通常越低。如在大面积草地场景

P2 Stability：当以下情况出现时，会减弱P2的抑制作用，将P2向100拉回，目的是为了防止统计不足时，P2把真正的主导光源压得过低。

- Neutral PB数量少；

- LV较低；

- 该光源P0较高。

最终这三者进行相乘得到最终 $$P(L_i)$$

每种光源先计算：$$Score(L_i)=P0(L_i)\times P1(L_i)\times P2(L_i)$$

再对所有光源归一化： $$P(L_i)=\frac{Score(L_i)}{\sum Score}\times100$$

**总结**

P0：统计数量，P1：场景亮度，P2：绿洋红偏移

> 注意这里的P1亮度统计与前面PB中weight的亮度权重区别。前面的亮度是这个统计块是否合理；P1是这种光源在当前整体亮度环境下是否合理。
> 
>

### Sunset Compensation

日落场景可能被归入Daylight类别，设个小框来针对性的改善日落场景。

在Daylight框（D65）内设定一个小框，该小框应包含日落主要落点。然后基于该小框内的落点再计算一个statistic gain，然后在该sunset gain和整个D65框的落点gain之间进行一个插值融合。该模块出发条件

1. 场景LV达到设定范围；

2. 大量日落天空点落入到4框（D65）

3. 日落区域中的统计块数量达到阈值；

4. 日落统计块占整框比率比较高；

最终Spatial Gain会通过一组权重与Statistic Gain进行融合

(1-W_i)\cdot SpatialGain(L_i)
$$

### F/CWF Subwindow Preference

该模块主要用于处理户外混淆色落入F和CWF框导致场景发冷蓝色。和P2一样都是为了解决混淆色问题。但该模块是为了解决P2无法筛去落入框内部的混淆色，如绿植及泥土等。

算法在F/CWF光源框内部再定义一个子区间。当满足以下条件时：

- 有一定比例的F/CWF Parent Block落入Subwindow；

- Parent Block靠近设定的强作用位置；

- 整帧LV达到启用范围；

### 最终输出

每种光源再得到上述加权后的Gain后，都会得到自己的修正后候选 $$EqvGain(L_i)$$。最后按照上一节得到的光源概率 $$P(L_i)$$ 加权：

$$
MixGain=
\sum_i P(L_i)\cdot EqvGain(L_i)
$$

---

整体流程

```text
每种光源的Statistic Gain
→ Prefer Color（T/WF/Shade）
→ Statistic Gain Constraint
→ 与Spatial Gain按Daylight Locus Probability融合
→ Equivalent Gain
→ × Preference Gain
→ 按光源概率P融合七类候选Gain
→ Mix Gain
```

## 参数定义

> **`i4LimitY`****、****`i4ProjWeight`****、****`i4WeightReduce`****、****`Mode`**
> 
> 

### **`i4LimitY`**

**`i4LimitY`**判断某光源的Statistic点在 Yr 方向**离 D65 有多远**。

例如 CWF：

```text
D65_Yr        = -389
Statistic_Yr  = -556
i4LimitY[CWF] = 123
```

先算超出允许范围多少：

$$
LIMIT_{CWF} = |StatisticYr-D65Yr|-i4LimitY
$$

### **`i4ProjWeight`**

当 Statistic 点超出 `i4LimitY` 后，即 $$LIMIT_{CWF}$$＞0，会把它往限制边界方向投影。

投影强度由参数**`i4ProjWeight`**决定：

- 16 = 完整投影

- 8  = 部分投影

- 0  = 不投影

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 28.png' | asset_url }})

> 其中AWB\_tag\_AVG\_YR\_CWF就是某光源的原始统计点坐标。
> 
> 

### **`i4WeightReduce`**

当判断超出设置i4LimitY距离后，就需要进行投影了，其中**`i4WeightReduce`**是用于控制投影权重参数

$$
ReduceProb=
LIMIT_{CWF}\times\frac{i4WeightReduce[X]}{16}
$$

> 可以看到该权重是0\-16的一个范围权重
> 
> 

最终计算得到`ReduceProb`后，即可以应用到最终光源概率**`Locus Probability`**上了，减去即可

![image\.png]({{ '/assets/ISP/remo-awb-theory/image.png' | asset_url }})

# 三、Extra Color Compensation

该模块用来解决 Confusion Color误导 AWB的问题，例如大面积绿植、青色玻璃、粉色/咖啡色物体等。

这些物体的统计点可能进入 AWB Light Area，被当成白点，导致光源概率或 Statistic Gain 被拉偏。Extra Color 会先识别这种特殊颜色，再针对 AWB 做补偿。

## 参数定义

一组 Extra Color 主要由下面几个条件共同决定：

- Left/Right/Upper/Lower Bound：定义 Xr/Yr 的特殊颜色区域

- Green Level：只有 G 落在范围内的 PB 才计数

- rLv\_L / rLv\_H：控制什么 LV 下生效

- rCount\_L / rCount\_H：控制需要多少特殊颜色 PB

- i4ConfThld：连续多少帧检测到后达到完整作用

- **`i4ModeWeight`**\[0\~2\]：Mode0/1/2 各自最大作用强度

- Select Light Source：Mode1/2 要作用于哪些光源

大致流程是：XrYr命中 → G满足 → Count足够 → LV满足 → Confidence建立 → 产生 Extra Weight。

---

## Extra Weight 初试权重

在进行最终权重计算时，他们首先统一会计算一个初始权重

该初试权重由**亮度、PB个数、自定义强度**共同决定

上一步得到的weight是下一步插值的最大值：

1. 初始权重

自定义`ModeWeight`结合以上最终得到的weighting，得到初始权重：

$$
W_{mode} =
\frac{ModeWeight}{256}
\times Weighting
$$

其中 `ModeWeight` 分别取 Mode0、Mode1、Mode2 自己的配置值。因此根据不同mode设置不同的权重ModeWeight，可得到他们各自所对应的初始权重

## Extra 最终影响

### Mode 0

提前配置： GainR,    GainG,    GainB

用上一节计算得到的初始权重 $$W_{mode0}$$控制当前 AWB Gain 向这个预设 Gain 补偿。

使用场景场景：Neutral PB 非常少，正常 AWB 已经没有足够白点。

注意该mode的作用位置非常靠后，影响相对较大，如无必要尽量不用

### Mode 1 

该模式降低指定光源的 **P2**。

公式：

$$
P2_{new} = 
P2_{original}
\times
\frac{100-W_{mode1}}{100}
$$

即降低该光源的可信度，进而降低它的最终光源 Probability。

适用于**多光源，**比如降低酒吧霓虹灯的影响:\)

---

### Mode 2 

该模式降低指定光源内部的 `Daylight Probability`，让当前光源向spatial gain进行偏移（当然，spatial gain要正确）

公式：

$$
DLProb_{new} = 
DLProb_{original}
\times
\frac{100-W_{mode2}}{100}
$$

适合于光源判断本身不一定错，但大量 Neutral PB 都是混淆色，导致 Statistic Gain 不可信。

---

总结：

- Mode0：AWB无法计算，交给预设Gain来；

- Mode1：光源判断错误，降低当前光源概率；多光源

- Mode2：光源没有判断错误，但光源的Gain受到其他物体影响，所以降低当前光源Gain\-\>spatial Gain

# 五、Face Assisted AWB

## 概述

Face Assisted AWB 用于 **混光、纯色背景、confuse color 等有人脸场景下，Normal AWB 光源判断容易被背景统计误导的问题**。它利用 Face ROI 的颜色信息独立预测当前光源/白平衡 Gain，再反过来修正 Normal AWB 的光源 Probability；自研 `Mode=1` 时还会进一步把 Face Predictor Gain 混入最终结果。MTK 对该模块的定义就是“使用 face color 预测 light source/gain，辅助 Normal AWB，并提高 confusing\-color scene 的准确率”。

![ChatGPT Image 2026年8月15日 10\_59\_02\.png]({{ '/assets/ISP/remo-awb-theory/ChatGPT Image 2026年8月15日 10_59_02.png' | asset_url }})

## 算法流程

1. **获取有效 Face Stats**

输入主要包括：

- Face ROI 的 R/G、B/G；

- Face Glevel；

- Hue；

- ROI 内 AWB Stats 的分布；

- Face Size、连续有效帧数；

- 当前曝光状态。

先判断 Face 是否可信，如果曝光异常、ROI 与 AWB Stats 重叠不足、Face Stats 分布过散，则降低 Face Assist Confidence，严重时模块不生效。

自研主要限制参数：

- ExposureErrorTolerance：当前曝光与标定目标曝光的容忍范围

- FaceRoiStatsBlockWeightThd：Face ROI 与有效 WB Stats 的重叠要求

- FaceStatsDistConfThd：ROI 内 Stats 坐标离散度限制

- FaceConfGlevelThd：过亮人脸的可信度限制

- FaceConfHueThd：Hue 合理性限制

- FaceStateChangeThd：有脸/无人脸状态切换的稳定帧数

其中 `FaceStatsDistConfThd` 越严格，阴阳脸、复杂混光等 Face Stats 离散场景越容易被降权。

---

2. **Glevel **

MTK 原始机制中，每个标准光源都有不同 G 节点对应的 `Reference Face XY`。当前 Face G 落在哪两个节点之间，就对该光源的 Reference Face XY 插值。

3. **Light Source Weight**

得到各 CT 当前对应的 Face Reference 后，将真实CurrentFaceXY和参考肤色进行位置/距离比较，计算当前 Face 更接近哪些标准光源。

> 这里权重计算时有两个模式Mode0、Mode1，Mode 1比0多了几个非标准光源
> 
> 

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 37.png' | asset_url }})

得到对应的参考肤色光源的权重后，将该权重同样应用与日光光源上，就可以得到理想日光光源坐标了

此时还需要进一步叠加上，face Reference和 face color之间的shift。因为实际光源肯定不会正好落在色温曲线上：

$$
IdealNeutralXY+FaceShiftXY
$$

> 如果 `Face-Shift-Y` 很大，则更可能意味着异常光源或 Face Stats 本身不可信。
> 
> 

4. **Face Predictor 修正 Normal AWB P3**

得到人脸对应光源后，此时就可以筛选真正的光源了。

MTK是采用人脸光源与各个估计光源距离的倒数得到概率来完成。

如果距离越大说明`P3 = 1 / distance`越小，那么将该P3乘上当前光源后，在最终计算中概率所占比例也就越小

> 即 Final Light Source= EQV \* P0\* P1\* P2\* P3
> 
> 

5. **Face Assist Mode**

**Mode 0**

只利用 Face Predictor **修改各 CT Final Probability / P3**

这种方式 Face Assist 只负责重新投票，不会直接强行塞一个 Face Gain，副作用相对小。

**Mode 1**

在 Mode0 修改 Probability 的基础上, 再混入一个新Gain值。融合比例按照Face Confidence 混合

# 七、Sky Color Compensation

## 1\. 概括

Sky Color Compensation 是 MTK 用于改善天空场景 AWB 偏色的独立补偿模块。主要通过颜色域检测 \+ 空间分布判断识别天空，再根据天空颜色、场景 LV、落点数量及连续检测帧数计算补偿 Gain，与原始 AWB Gain 混合得到最终增益。

整体流程：Sky Color Window 筛选 → 空间分布检测 → 计算 Weighting → XrIndex 查表获得补偿 Gain → 混合原始 AWB Gain

## 2\. Sky Detection

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 19.png' | asset_url }})

### 2\.1 颜色域检测

在 XrYr 空间中设置 Sky Color Window，筛选落入窗口且满足 GLevel 范围的统计块（PB）。

参数：

- `i4LeftBound / RightBound`：天空颜色框 Xr 边界。

- `i4UpperBound / LowerBound`：天空颜色框 Yr 边界。

- `rGlevel`：有效统计块 GLevel 范围。

### 2\.2 空间域检测

将画面划分为 Top、Bottom、Left、Right 四个 1/3 区域，分别计算：

- 计算四个区域的 Sky PB 数量，然后得到 MaxCount、MinCount、AvgCount。

- 各区域平均 B 值。

- 各区域 Sky PB 的平均 XrYr 坐标。

需要同时满足以下三个条件，才会判定为 Sky Detected：

1. $$MaxCount-AvgCount>rCount_L/2$$

2. $$SceneLV\text{ 在有效范围内}$$

3. $$MaxBAvgWin=MaxSkyCountWin$$

其中：

- `MaxCount - AvgCount`：判断天空颜色是否存在空间集中性。

- `MaxBAvgWin = MaxSkyCountWin`：平均 B 值最高的区域与天空候选落点最多的区域一致。

## 3\. Compensation

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 6.png' | asset_url }})

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 16.png' | asset_url }})

![image\.png]({{ '/assets/ISP/remo-awb-theory/image 8.png' | asset_url }})

### 3\.1 Weighting

最终补偿强度由三个因素共同决定：

① SceneLV → i4Weighting1

根据 LV 和 `rWeighting` 计算基础补偿强度。

- `i4LvRange != 0`：梯形权重曲线，LV 在 `rLv_L～rLv_H` 时达到最大权重，两侧通过 LvRange 平滑过渡。

- `i4LvRange = 0`：使用随 LV 增大而上升的权重曲线。

② MaxCount → i4Weighting2

根据 Sky PB 最大数量进一步调整强度。MaxCount 越大，补偿越强，达到 `rCount_H` 后不再增加。

③ Confidence → i4Weighting

根据连续检测到天空的帧数进行平滑：

$$
Weighting=Weighting2\times \min\left(1,\frac{FrameCnt}{i4ConfThr}\right)
$$

连续检测帧数达到 `i4ConfThr` 后使用完整补偿强度，避免天空检测状态变化时产生明显色彩跳变。

### 3\.2 Compensation Gain

选取 MaxSkyCountWin 区域内 Sky PB 的平均 Xr，将其归一化到 0～100：

$$
XrIndex=\frac{Xr-XrL}{XrR-XrL}\times100
$$

再根据 XrIndex 查询 Sky Gain LUT，通过插值得到对应的 R/B 补偿增益。

MTK增益LUT：

随着 XrIndex 增大，该示例 LUT 中 R Gain 逐渐减小，B Gain 逐渐增大，补偿方向整体趋冷。

### 3\.3 最终 Gain 混合

将 Sky Compensation Gain 与原始 Target Gain 根据 Weighting 混合：

$$
Gain_{out}=(1-w)Gain_{in}+wGain_{sky}
$$

其中 $$w=Weighting/100$$。

- Weighting = 0：完全使用原始 AWB Gain。

- Weighting = 100：完全使用 Sky Compensation Gain。

- 中间值：按比例混合两组 Gain。

该补偿作用于全局 AWB Gain，而非仅改变天空区域的颜色。

# 八、Golden和Unit校准

## 原理

AWB 校准的目的是：**补偿不同相机模组的颜色响应差异，让基于 Golden 调好的参数能够适用于每台 Unit。**

1. 采集标定数据
Golden 与每台 Unit 分别在 5000K、3000K 光源下拍摄中性目标，获得配对的 R/G、B/G 坐标或对应中性增益。Golden 数据可作为公共参考保存，每台 Unit 单独标定。

2. 建立对应关系
将标定增益转换为落点坐标，利用两个光源的对应点，分别确定 R、B 两个维度的直线方程：

3. $$x_U=a_Rx_G+b_R,\quad y_U=a_By_G+b_B$$

4. 其中，斜率负责缩放，截距负责平移。

5. 校准窗口与参考增益
Golden 窗口的左右边界使用 X 变换，上下边界使用 Y 变换，生成适配 Unit 的判白窗口。参考增益则经过“增益 → 坐标 → 校准 → 增益”的转换。程序在相关步骤进行整数截断。

6. 参与实际 AWB 计算
Unit 使用校准后的窗口和参考参数进行判白、光源估计及后续增益计算。

> Golden 建立参考标准 → 双光源测出 Unit 差异 → 缩放和平移参考坐标 → 让同一套 AWB 参数适配当前相机。

## 整体流程

算法流程

```text
┌──────────────────────────────────────────────────────────────┐
│  原始统计 → 判白/色温估计 → 计算目标增益 T      │
│                              ↓                               │
│  isConvOut? ──是──→ 冻结 A = 当前输入增益                     │
│       │                                                     │
│       ↓                                                     │
│  isConvIn? ──是──→ 跳过，P 不变，ALG_GAIN = P                 │
│       │                                                     │
│       否                                                    │
│       ↓                                                     │
│  getSmoothNextGain(T, A, P, speed, fps):                    │
│    d=T-A, r=T-P, α=S/256                                   │
│    ┌─ P+d·α 跨过 T？──→ step = r·α（防过冲）                  │
│    ├─ |r|≥|d|？───────→ step = r·α（尚远离，大步追）           │
│    └─ 否则 ──────────→ step = d·α（匀速追踪）                  │
│       ↓                                                     │
│  ALG_GAIN = P + step（向零截断，至少 ±1）                      │
│       ↓                                                     │
│  Platform Gain = ALG_GAIN → 写入硬件寄存器                    │
│       ↓                                                     │
│  updateAwbInput: 回填 P = Platform Gain，供下帧使用            │
└──────────────────────────────────────────────────────────────┘
```

其中：

## 距离及收敛判定

$$
D^2 = (Rtarget1024 - Rcurrent1024)² + (Btarget1024 - Bcurrent1024)²
$$

- 参数`isConvIn` 判断 `D2 <= ConvIn²`；

- 参数`isConvOut` 判断 `D2 >= ConvOut²`。

例如 ConvIn=36、ConvOut=64 ：

- 未收敛时，距离 \<=36 才标记收敛；

- 已收敛时，距离 \>=64 才退出。中间距离保留原状态。

## 速度比例、帧率与取整

有效速度按 `S/256` 参与步长计算。32 对应 12\.5%，2 对应 0\.78125%，所以值越大越快。

函数还计算：

```text
k = ceil((input_frame_rate - 5) / 30)
if k > 0:
    S = ceil(table_speed / k)
Speed = S
```

例如输入帧率 30 时 k=1，表中 32 得到有效速度 32；60 时 k=2，得到 16。

## 收敛过程

定义目标增益为 T、参考增益 A、上一输出增益 P。

> 其中参考增益 A是 ConvOut 触发时冻结的输入增益。
> 
> 

```text
d = T - A     （目标相对参考的偏移，A 冻结后 d 恒定）
r = T - P     （剩余差距，每帧随 P 移动而缩小）
α = S / 256   （有效速度比例）
```

收敛过程如下：

```text
┌─────────────┐
                    │ P + d·α     │
                    │ 会不会跨过T？ │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │ 是 (跨过)              │ 否
              ▼                       ▼
```
